# 1.2. Глубина дерева

**Тип:** ответы. Ничего создавать не нужно, нужно измерить индекс и записать числа в `answers.yaml`.

## Сценарий

Перед проверкой уже создан индекс по дате заказа:

```sql
CREATE INDEX orders_created_at_idx ON orders (created_at);
```

Его создаёт `setup.sql` задания. Чтобы поиграть с индексом в `lab psql`, выполните `lab reset`, а затем `\i modules/01-anatomy/tasks/1.2-tree-depth/setup.sql`.

## Что сделать

С помощью `pageinspect` (раздел 4 в README модуля и [cheatsheet.md](../../cheatsheet.md)) ответьте в `answers.yaml`:

1. `level`: сколько уровней у дерева **над** листьями.
2. `depth`: сколько страниц индекса читается при спуске от корня до листа.
3. `root_items`: сколько записей (`live_items`) в корневой странице.
4. `leaf_pages`: сколько всего листовых страниц.
5. `entries_per_leaf`: сколько в среднем записей на одном листе, округлите до целого. Допускается погрешность 5%.
6. `lookup_buffers`: **прогноз**: сколько страниц покажет `Buffers` у `EXPLAIN (ANALYZE, BUFFERS)` при поиске одного заказа по точному значению `created_at`. Сначала посчитайте на бумаге, потом проверьте: возьмите `created_at` заказа 123456 и найдите его по этой дате.

Запустите `lab check 1.2`.

После PASS ответьте себе: на сколько вырастет `level`, если строк станет в 100 раз больше?
