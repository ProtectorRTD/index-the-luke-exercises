# 1.8. Прогноз числа страниц

**Уровень:** расчёт. Сначала считаем на бумаге, потом сверяем с `EXPLAIN`.

## Зачем

Умение прикинуть, сколько страниц прочитает запрос, до его запуска — главный практический навык модуля. Если прогноз сходится с фактом, вы понимаете, как работает индекс. Если расходится в разы, вы нашли пробел.

## Сценарий

`setup.sql` создаёт два индекса:

```sql
CREATE INDEX orders_created_at_idx ON orders (created_at);
CREATE INDEX customers_created_at_idx ON customers (created_at);
```

Важное отличие между таблицами:

- **заказы** лежат на диске в порядке `created_at`: соседние по дате заказы лежат на соседних страницах;
- **клиенты** лежат вразброс: дата регистрации никак не связана с положением строки.

## Модель

Чтение по индексу — это три слагаемых:

```
страниц = спуск по дереву + листья индекса + страницы таблицы
```

- спуск: глубина дерева, вы мерили её в задании 1.2;
- листья: `найдено_строк / записей_на_листе`;
- страницы таблицы: зависит от того, как строки лежат на диске.

## Что сделать

1. `lab reset`, в `lab psql` выполните `\i modules/01-anatomy/tasks/1.8-predict-pages/setup.sql`.
2. Измерьте исходные числа и впишите в `answers.yaml`:
   - `rows_per_heap_page`: сколько строк `orders` в среднем на одной странице таблицы. Допуск 3%.
   - `entries_per_leaf`: сколько записей в среднем на листе `orders_created_at_idx`. Допуск 5%.
3. Для каждого запроса ниже **сначала посчитайте прогноз**, потом выполните `EXPLAIN (ANALYZE, BUFFERS)` два раза подряд и возьмите `Buffers` верхнего узла из второго прогона. В `answers.yaml` впишите фактическое число, допуск 10%.

| Ответ | Запрос |
| --- | --- |
| `pk_buffers` | `SELECT * FROM orders WHERE id = 424242` |
| `week_rows`, `week_buffers` | `SELECT * FROM orders WHERE created_at >= '2024-03-04' AND created_at < '2024-03-11'` |
| `quarter_buffers` | `SELECT * FROM orders WHERE created_at >= '2024-04-01' AND created_at < '2024-07-01'` |
| `scattered_rows`, `scattered_buffers` | `SELECT * FROM customers WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01'` |

4. `lab check 1.8`.

Почему два прогона: при первом обращении к индексу в сессии Postgres дополнительно читает его служебную страницу, и число получается на несколько страниц больше.

Цель задания считается достигнутой, если ваш прогноз до запуска отличался от факта не больше чем на 15% для недели и квартала. Для последнего запроса простая формула «строки / строк на странице» даст ошибку в десятки раз. Разберитесь почему, прежде чем открывать подсказки.
