# 1.6. Стоимость плана по формуле

**Уровень:** расчёт. Ничего создавать не нужно: считаем то же, что считает планировщик.

## Зачем

Планировщик выбирает план с наименьшей стоимостью (`cost`). Пока `cost` выглядит случайным числом, его выбор кажется магией. В этом задании вы получите число из `EXPLAIN` на калькуляторе.

## Запрос

```sql
SELECT * FROM customers WHERE country = 'SK';
```

Индексов по `country` нет, план — `Seq Scan`.

## Формула

Стоимость `Seq Scan` складывается из трёх частей:

```
cost = число_страниц × seq_page_cost
     + число_строк   × cpu_tuple_cost
     + число_строк   × cpu_operator_cost      (по одному разу на каждое условие в WHERE)
```

Откуда брать числа:

- число страниц и строк таблицы, как их видит планировщик: `pg_class.relpages` и `pg_class.reltuples`;
- три коэффициента: `SHOW seq_page_cost;` и так далее;
- оценка числа строк в результате: `reltuples ×` доля значения `'SK'` из статистики. Доля лежит в `pg_stats.most_common_freqs`, на той же позиции, что `'SK'` в `most_common_vals`.

## Что сделать

Сначала посчитайте, потом сверьте с `EXPLAIN`. Впишите в `answers.yaml`:

1. `relpages`, `reltuples`: что планировщик знает о таблице.
2. `seq_page_cost`, `cpu_tuple_cost`, `cpu_operator_cost`: коэффициенты.
3. `seq_scan_cost`: стоимость по формуле. Это второе число в `cost=0.00..X` у `Seq Scan`.
4. `freq_sk`: доля `'SK'` по статистике, число от 0 до 1.
5. `estimated_rows`: сколько строк планировщик ожидает в результате.
6. `actual_rows`: сколько их на самом деле.
7. `seq_scan_cost_ua`: стоимость `Seq Scan` для того же запроса с `country = 'UA'`. Сначала ответьте, не запуская.
