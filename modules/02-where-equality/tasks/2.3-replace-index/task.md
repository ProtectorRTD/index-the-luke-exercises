# 2.3. Заменить унаследованный индекс

**Тип:** индексы. Запросы менять нельзя.

## Сценарий

На журнале действий `events` уже есть индекс. Его когда-то сделали под отчёт по покупкам, `setup.sql` создаёт его перед проверкой:

```sql
CREATE INDEX events_type_user_id_idx ON events (type, user_id);
```

Отчёт по покупкам (`a.sql`) работает быстро:

```sql
SELECT count(*) FROM events WHERE type = 'purchase' AND user_id = 17;
```

Теперь появилась лента действий пользователя (`b.sql`), и она медленная:

```sql
SELECT id, type, created_at FROM events WHERE user_id = 54321;
```

`events` — журнал, в который постоянно пишут, и каждый лишний индекс замедляет вставку. Правило команды: на `events` не больше одного индекса, кроме первичного ключа.

## Что сделать

1. Заполните `prediction.md`.
2. `lab reset`, в `lab psql` выполните `\i modules/02-where-equality/tasks/2.3-replace-index/setup.sql` и посмотрите планы обоих запросов.
3. В `solution.sql` приведите индексы на `events` к такому виду, чтобы быстрыми были оба запроса.
4. `lab check 2.3`.

## Как проверяется

- на `events` не больше одного индекса, кроме первичного ключа;
- `a.sql`: обе колонки в `Index Cond`, фильтром не отброшено ни одной строки;
- `b.sql`: `user_id` в `Index Cond`, не больше 40 страниц.
