# 2.9. После ночной загрузки

**Уровень:** расследование. В чём причина, задание не говорит.

## Сценарий

Таблица `refunds` хранит заявки на возврат денег. На ней два индекса: по статусу и по клиенту. Оператор открывает новые заявки клиента (`query.sql`):

```sql
SELECT id, amount, created_at
FROM refunds
WHERE status = 'new' AND customer_id = 4242;
```

Вчера запрос выполнялся мгновенно. Ночью из старой системы загрузили 100 000 заявок в статусе `new`, и с утра операторы жалуются: тот же запрос стал заметно медленнее.

`setup.sql` воспроизводит ситуацию: создаёт таблицу и индексы, а затем выполняет ночную загрузку.

Ограничения: запрос менять нельзя, новые индексы создавать нельзя, существующие удалять нельзя.

## Что сделать

1. `lab reset`, в `lab psql` выполните `\i modules/02-where-equality/tasks/2.9-after-nightly-load/setup.sql`.
2. Найдите причину. Сформулируйте её одной фразой, с числами из плана.
3. Устраните причину в `solution.sql`.
4. `lab check 2.9`.

## Как проверяется

- новых индексов нет, оба существующих на месте;
- запрос читает не больше 150 страниц;
- оценка числа строк в плане расходится с фактом не больше чем в 5 раз.
