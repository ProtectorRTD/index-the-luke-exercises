# 2.2. Один индекс на два запроса

**Тип:** индексы. Запросы менять нельзя.

## Сценарий

Страница клиента выполняет два запроса. Сводка в `q1.sql`:

```sql
SELECT count(*), sum(total) FROM orders WHERE customer_id = 17;
```

Вкладка «Отменённые» в `q2.sql`:

```sql
SELECT id, created_at, total FROM orders WHERE customer_id = 17 AND status = 'cancelled';
```

DBA разрешил добавить на `orders` **один** индекс. Он должен ускорить оба запроса.

## Что сделать

1. Заполните `prediction.md`.
2. Попробуйте в psql оба варианта порядка колонок и посмотрите на `Buffers` у каждого запроса.
3. Запишите выбранный индекс в `solution.sql`.
4. `lab check 2.2`.

## Как проверяется

- создан ровно один новый индекс;
- `q1.sql`: `customer_id` в `Index Cond`, не больше 700 страниц;
- `q2.sql`: обе колонки в `Index Cond`, фильтром не отброшено ни одной строки, не больше 30 страниц.

После PASS ответьте себе: почему у неправильного варианта в плане `q1.sql` тоже написано `Index Cond: (customer_id = 17)`, а страниц в несколько раз больше?
